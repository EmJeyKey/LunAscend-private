## Scientific presentation definitions

- **Sunlight timeline:** one mark for each returned observation timestamp. It maps
  the actual terrain classification to modeled center obstruction, potential Sun
  clearance within evaluated coverage, unknown or not calculated. Positive geometric
  elevation alone never becomes terrain visibility or electrical generation.
- **Earth timeline:** actual DTE access classifications when present, otherwise the
  terrain-center classification. Below the equipment clearance requirement remains
  distinct from modeled obstruction. Unknown/missing samples remain unknown.
- **Selected time:** exact UTC matching connects the summary, timelines, W/Wh/SOC
  readouts, original charts and Explorer cursor. Pointer selection chooses an existing
  sample; keyboard-accessible range controls remain available. No new science request
  or interpolated visibility transition is generated by moving the cursor.
- **Solar plot:** actual backend `solar_generation_w`, in W, for conservative and
  optimistic cases. It uses the existing panel area, efficiency, orientation,
  irradiance, terrain and loss assumptions. No power result means no power curve.
- **Battery plot:** actual `battery_energy_wh`, in Wh, with the backend model outcome
  and visible load/capacity/reserve assumptions. Null samples break quantitative lines.
  Dots are returned samples; connecting lines are a visual guide, not new values or
  exact depletion times. Existing detailed accounting and DTE intervals remain in
  the technical disclosures.
- **Outcome language:** “only the optimistic case meets the configured battery
  model” never means guaranteed spacecraft survival. Potential Earth access never
  means a working radio link. No RF signal-strength percentage, illumination intensity
  inferred from elevation, suitability score or favorable replacement for unknowns exists.

Central mappings and comparisons live in `lib/humanize.ts`. Reusable UI consists of
`PresentationControls`, `ScientificDetails`, `SourceInfo`, `OperationalConditions`,
`SampleTimeline`, `ModelPowerPlot`, `SimpleEngineering`, `FriendlyComparison` and
the contextual 16-term glossary. `MissionContext` adds only presentation bookkeeping
to explain cleared results; its existing cancellation/version protections remain.

## Data transparency and provenance

“Where does this data come from?” is accessible beside the explained timelines,
engineering, comparison and resilience sections. Explorer provides “Where does this
image come from?” and terrain source explanations. Source records resolve the existing
offline catalog and imagery manifest rather than copying product versions into UI code.
Provider/product, frame, resolution qualifications, original URLs, usage conditions,
attribution, limitations and offline requirements remain available. Missing metadata
is explicitly unavailable. Mock explanations reject NASA scientific lineage claims.

The distinctions are explicit: **SPICE** supplies astronomical model outputs;
**LOLA** supplies measured elevations; **LROC WAC/NAC** supplies archived photographs;
**LunAscend** derives horizons, power, battery, conditional DTE and mission comparisons;
users supply hardware/mission assumptions. NASA does not approve these conclusions.
Exact image-to-local-DEM registration remains unverified; photographic shadows are
historical and local DEM optical draping remains withheld.

QuickMap stays an external reference. Moon Trek serves the existing photographic
products and remains an external exploration reference. CSA supplies educational
context. Horizons remains saved cross-implementation comparison evidence with shared
JPL heritage, not fully independent observational validation. All 36 saved comparison
rows, original kernels/LOLA manifests and scientific reference outputs remain unchanged.
Rights and source identities remain in [the source documentation](OFFICIAL_RESOURCES.md)
and [the imagery report](STEP_11_6_ORIGINAL_NASA_MAPS.md). No agency endorsement is implied.
